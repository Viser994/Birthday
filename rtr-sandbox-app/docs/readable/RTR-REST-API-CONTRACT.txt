Payments Canada RTR Sandbox — REST API Contract

Share this with the application development team for REST integration.

Base URL (sandbox): https://api.payments.ca
RTR path prefix: /rtr-sandbox
Portal product required: rtr-sandbox-product
Spec style: ISO 20022 JSON (Payments Canada sandbox mapping)
Official portal: https://developer.payments.ca/rtr-sandbox-api/apis

  Captured from live sandbox calls on 2026-07-20. Sandbox responses are
  stubbed test data.

------------------------------------------------------------------------

0) Integration sequence (recommended)

    1. POST /accesstoken                         → Bearer token
    2. POST /rtr-sandbox/inbound-heartbeat       → health check
    3. POST /rtr-sandbox/payments                → send pacs.008
    4. POST /rtr-sandbox/payments/status         → enquire pacs.028
    5. POST /rtr-sandbox/interest-report         → optional C&S report
    6. POST /rtr-sandbox/payment-capacity-balance-report → optional balance

------------------------------------------------------------------------

1) Common conventions

Content type

  --------------------------------------------------------------------------------------------
  Direction               Header                  Value
  ----------------------- ----------------------- --------------------------------------------
  Request (RTR APIs)      Content-Type            application/vnd.api.v1+json

  Request (RTR APIs)      Accept                  application/vnd.api.v1+json

  Request (token)         Content-Type            application/x-www-form-urlencoded

  Response (RTR APIs)     Content-Type            application/vnd.api.v1+json; charset=utf-8

  Response (token)        Content-Type            application/json
  --------------------------------------------------------------------------------------------

Common RTR request headers

  --------------------------------------------------------------------------------------------
  Header            Required          Description       Example
  ----------------- ----------------- ----------------- --------------------------------------
  Authorization     Yes               Bearer access     Bearer <ACCESS_TOKEN>
                                      token             

  Content-Type      Yes               RTR media type    application/vnd.api.v1+json

  Accept            Recommended       RTR media type    application/vnd.api.v1+json

  x-uetr            Recommended       UUID for payment  899860fa-1b98-45df-b8aa-c56d8df0f047
                                      tracking          
                                      (pacs.008 /       
                                      pacs.028)         

  traceability-id   Recommended       UUID for          e23d32eb-c7f2-4836-a314-557efe95a525
                                      end-to-end        
                                      tracing           

  x-jws-signature   Spec says         JWS of payload;   <JWS>
                    required          sandbox often     
                                      accepts without   
                                      it                
  --------------------------------------------------------------------------------------------

Typical HTTP statuses

  -----------------------------------------------------------------------
  Status                              Meaning
  ----------------------------------- -----------------------------------
  200                                 Business response returned (may
                                      still be reject via admi.002)

  400                                 Bad request / validation

  401                                 Missing/invalid token, or wrong API
                                      product on app

  403                                 Forbidden

  429                                 Too many requests

  500 / 503                           Server / unavailable
  -----------------------------------------------------------------------

Important product note

Token must be issued for an app with product rtr-sandbox-product.
If the app is payments-rail-sandbox, token works but RTR calls return:

    {
      "code": "invalid_token",
      "message": "Invalid token. Please generate token for correct API Application."
    }

2) Generate Access Token

Endpoint

POST https://api.payments.ca/accesstoken

Headers

    Authorization: Basic <BASE64(CONSUMER_KEY:CONSUMER_SECRET)>
    Content-Type: application/x-www-form-urlencoded

Request body (form)

    grant_type=client_credentials
    scope=client_credentials

cURL

    curl -X POST "https://api.payments.ca/accesstoken" \
      -u "$CONSUMER_KEY:$CONSUMER_SECRET" \
      -H "Content-Type: application/x-www-form-urlencoded" \
      -d "grant_type=client_credentials&scope=client_credentials"

Success response (200)

    {
      "token_type": "Bearer",
      "access_token": "<ACCESS_TOKEN>",
      "expires_in": "1799",
      "status": "approved",
      "api_product_list": "[rtr-sandbox-product]",
      "api_product_list_json": ["rtr-sandbox-product"],
      "organization_name": "paymentscanada",
      "client_id": "<CONSUMER_KEY>",
      "application_name": "<APP_UUID>",
      "issued_at": "1784507712073",
      "refresh_token_expires_in": "0",
      "refresh_count": "0",
      "scope": ""
    }

Notes for developers

-   Cache token and refresh before expiry (expires_in ≈ 30 minutes
    observed; portal docs historically mention shorter windows — always
    use expires_in).
-   Send as Authorization: Bearer <access_token> on all RTR calls.

8) Status / reject codes cheat sheet

  -----------------------------------------------------------------------
  Code                    Where                   Meaning
  ----------------------- ----------------------- -----------------------
  ACSP                    pacs.002                Accepted for settlement
                          transaction_status      

  ACSC                    pacs.002                Settlement completed

  RJCT                    pacs.002                Rejected

  PDNG                    pacs.002                Pending

  FF01 / FF02             admi.002 reject reason  Format / schema
                                                  validation failure

  HBRT                    admi.004 / admi.011     Heartbeat event
  -----------------------------------------------------------------------

9) Minimal client pseudocode

    token = POST /accesstoken (Basic auth)
    headers = {
      Authorization: Bearer token.access_token
      Content-Type: application/vnd.api.v1+json
      Accept: application/vnd.api.v1+json
      x-uetr: <uuid>
      traceability-id: <uuid>
    }

    heartbeat = POST /rtr-sandbox/inbound-heartbeat

    paymentReq = build pacs.008
    paymentRes = POST /rtr-sandbox/payments
    if paymentRes.message_reject -> show reject
    else status = paymentRes.fi_to_fi_payment_status_report...transaction_status

    statusReq = build pacs.028 using payment UETR / E2E / message id
    statusRes = POST /rtr-sandbox/payments/status
